# 核销单功能规划文档

## 一、概念说明

### 1.1 什么是核销单

核销单（Write-off Document）是 ERP 系统中用于记录**实际收付款行为**的财务凭证。它的核心作用是：将银行账户中真实的资金流入/流出，与系统中的应收账款/应付账款进行逐笔匹配和冲销。

通俗理解：
- **应收账款** = 客户欠我们的钱（债权）
- **应付账款** = 我们欠供应商的钱（债务）
- **核销单** = 实际收到/付出这笔钱的动作记录

### 1.2 核销单与对账单的关系

| 维度 | 对账单（Settlement Statement） | 核销单（Write-off Document） |
|------|-------------------------------|------------------------------|
| **本质** | 对账确认——双方确认交易金额和发票 | 收付款执行——记录资金实际到账/付出 |
| **时序** | 先发生 | 后发生 |
| **关注点** | 金额是否正确、发票是否齐全 | 钱是否到账、冲销了哪笔账款 |
| **状态影响** | 更新开票状态（未开票/部分开票/已开票） | 更新结算状态（未结算/部分结算/已结算） |
| **关系** | 一对多：一张对账单可对应多笔应收/应付 | 一对多：一张核销单可冲销多笔应收/应付 |
| **相互独立性** | 不依赖核销单存在 | 不依赖对账单存在——可直接核销未经对账的账款 |

> **重要说明：** 对账单和核销单是两条独立的业务链。核销单可以直接核销应收/应付账款，无需先生成对账单。对账单管理的是"发票流"，核销单管理的是"资金流"，两者通过应收/应付账款间接关联。

**典型业务流程（三种场景）：**

```
场景一：完整流程
出库单/入库单 → 自动生成应收/应付账款 → 生成对账单（确认金额+发票）→ 生成核销单（冲销账款）

场景二：跳过对账，直接收款/付款
出库单/入库单 → 自动生成应收/应付账款 → 生成核销单（冲销账款）

场景三：分期核销
出库单 → 应收账款 10万 → 核销单1（收3万）→ 核销单2（收5万）→ 核销单3（收2万）→ 已结算
```

## 二、现有系统分析

### 2.1 当前数据模型

**应收账款表 `receivables`：**
| 字段 | 说明 | 核销单关联 |
|------|------|-----------|
| `amount` | 应收总额 | 核销目标金额 |
| `received_amount` | 已收金额 | ⚠️ 已有字段，但未被使用 |
| `balance_amount` | 余额 | `amount - received_amount` |
| `status` | 结算状态：0=未结算，1=部分结算，2=已结算 | 核销单写入后更新 |
| `billing_status` | 开票状态 | 由对账单管理，与核销单无关 |
| `handling_fee` | 手续费 | 核销时需考虑是否包含手续费 |
| `payment_method` | 结算方式 | 可作为核销单付款方式的默认值 |

**应付账款表 `payables`：** 结构与应收一致。

**对账单表 `settlement_statements`：**
- 关联多条应收/应付的明细项（`settlement_statement_items`）
- 管理开票记录（`settlement_invoice_records`）
- 跟踪 `total_amount`、`invoiced_amount`、`uninvoiced_amount`

### 2.2 当前缺口

1. `receivables.received_amount` 和 `receivables.balance_amount` 字段已存在但**从未被写入**
2. `payables` 同理
3. 没有任何机制记录"谁在什么时候收/付了多少钱"
4. 应收/应付的 `status` 字段无法被自动化更新
5. **历史数据一致性**：已有数据的 `received_amount=0, balance_amount=0`，需要初始化脚本将 `balance_amount` 补为 `amount` 值

## 三、核销单功能设计

### 3.1 数据模型设计

#### 3.1.1 核销单主表 `write_off_documents`

```sql
CREATE TABLE write_off_documents (
  write_off_id       VARCHAR(36) PRIMARY KEY,     -- 核销单ID
  write_off_number   VARCHAR(50) NOT NULL UNIQUE,  -- 核销单编号，如 hx20260920001
  type               TINYINT NOT NULL,             -- 1=应收核销（收款），2=应付核销（付款）
  entity_id          VARCHAR(50) NOT NULL,         -- 客户代码/供应商代码
  entity_name        VARCHAR(100),                 -- 客户名称/供应商名称
  write_off_date     DATE NOT NULL,                -- 核销日期（实际收付款日期）
  total_amount       DECIMAL(14,4) DEFAULT 0,      -- 本次核销总金额（自动汇总明细）
  payment_method     VARCHAR(50),                  -- 收付款方式（银行转账/现金/承兑等）
  bank_reference     VARCHAR(100),                 -- 银行流水号/回单号
  remarks            TEXT,                          -- 备注
  status             TINYINT DEFAULT 1,            -- 1=已核销，0=已作废
  document_date      DATE,                         -- 制单日期
  create_time        DATETIME DEFAULT CURRENT_TIMESTAMP,
  update_time        DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

#### 3.1.2 核销单明细表 `write_off_items`

```sql
CREATE TABLE write_off_items (
  item_id            VARCHAR(36) PRIMARY KEY,
  write_off_id       VARCHAR(36) NOT NULL,         -- 所属核销单
  source_type        TINYINT NOT NULL,             -- 1=应收，2=应付（冗余字段，与主表type一致）
  source_id          VARCHAR(36) NOT NULL,         -- 对应的 receivable_id / payable_id
  source_bill_id     VARCHAR(50),                  -- 来源单据号（出库单号/入库单号）
  target_amount      DECIMAL(14,4) DEFAULT 0,      -- 该笔应收/应付的总金额（快照）
  write_off_amount   DECIMAL(14,4) DEFAULT 0,      -- 本次核销金额
  before_received    DECIMAL(14,4) DEFAULT 0,      -- 核销前已收/已付金额（快照，用于审计）
  after_received     DECIMAL(14,4) DEFAULT 0,      -- 核销后已收/已付金额（= before + write_off）
  remarks            VARCHAR(200),
  create_time        DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (write_off_id) REFERENCES write_off_documents(write_off_id)
);
```

#### 3.1.3 字段设计说明

| 设计决策 | 说明 |
|---------|------|
| `before_received / after_received` | 快照字段，记录核销瞬间的金额状态，用于审计追溯，即使后续有新的核销也不会被覆盖 |
| `target_amount` | 快照该笔账款的总金额，避免账款被修改后历史核销记录不可读 |
| `source_type` | 虽然与主表 `type` 冗余，但简化了明细查询，无需 JOIN 主表即可知道关联的是应收还是应付 |
| `total_amount` | 由后端自动汇总明细的 `write_off_amount` 之和，前端不传 |

### 3.2 核心业务逻辑

#### 3.2.1 创建核销单流程

```
用户操作：
1. 选择核销类型（应收核销 / 应付核销）
2. 选择客户/供应商
3. 系统自动加载该实体下所有"未结算"和"部分结算"的应收/应付账款
4. 用户填写每笔账款的本次核销金额
5. 系统自动校验：核销金额 ≤ 未核销余额（balance_amount）
6. 提交 → 事务写入核销单 + 更新应收/应付状态
```

**也可从应收账款/应付账款列表页发起：** 选中若干行 → 点击"生成核销单" → 自动填充选中的账款到核销明细（类似现有的"生成对账单"交互）。

#### 3.2.2 状态更新规则

提交核销单时，逐条更新关联的应收/应付账款：

```
对每条核销明细（需 SELECT ... FOR UPDATE 加行锁）：
  -- 重新读取最新余额（防止并发核销导致超额）
  current = SELECT received_amount, amount FROM receivables WHERE receivable_id = ? FOR UPDATE

  -- 校验
  if (current.received_amount + write_off_amount > current.amount)
    → 拒绝，返回错误："核销金额超出未核销余额"

  -- 更新
  receivable.received_amount = current.received_amount + write_off_amount
  receivable.balance_amount  = receivable.amount - receivable.received_amount

  -- 计算状态
  if (received_amount == 0)         → status = 0（未结算）
  else if (received_amount < amount) → status = 1（部分结算）
  else                               → status = 2（已结算）
```

#### 3.2.3 编辑核销单流程

> **注意：** 编辑核销单涉及资金回溯，仅允许编辑状态为"已核销"的单据，且需在事务中完成。

```
编辑流程（事务处理）：
  1. 读取原核销单的所有明细
  2. 对每条旧明细：回滚应收/应付（received_amount -= old_write_off_amount）
  3. 重新校验新明细的核销金额
  4. 对每条新明细：应用核销（received_amount += new_write_off_amount）
  5. 更新核销单主表和明细表
  6. 重新计算所有涉及的应收/应付状态
```

#### 3.2.4 作废核销单

```
作废流程（事务处理）：
  对每条核销明细（需加行锁）：
    current = SELECT received_amount FROM receivables WHERE receivable_id = ? FOR UPDATE

    -- 安全校验：作废后的 received_amount 不能为负
    if (current.received_amount < item.write_off_amount)
      → 拒绝，返回错误："数据异常，无法作废"

    receivable.received_amount -= item.write_off_amount
    receivable.balance_amount   = amount - received_amount
    重新计算 status

  UPDATE write_off_documents SET status = 0
```

> **设计决策：** 使用"作废"（软删除）而非物理删除，保留完整的审计轨迹。作废后的核销单仍可查看，但不可再编辑或重新启用。

#### 3.2.5 与手续费（handling_fee）的关系

现有系统中，对账单会将手续费分摊到关联的应收/应付账款上。核销时需注意：

```
核销金额的计算基准：
  应核销总额 = amount + handling_fee（应收总额 + 手续费）

  当前系统中 receivable.amount 已经是出库单的 total_amount，
  handling_fee 是独立字段。核销单加载待核销账款时，
  应显示「可核销余额 = amount + handling_fee - received_amount」。
```

### 3.3 与对账单的联动

| 场景 | 联动方式 |
|------|---------|
| 对账单生成后 | 不影响核销单，两者独立 |
| 核销单核销后 | **不改变**对账单的开票状态，只改变应收/应付的结算状态 |
| 查看应收/应付详情 | 可同时看到关联的对账单记录和核销单记录 |
| 对账单汇总页面 | 可考虑增加"已核销总额"统计 |

### 3.4 数据一致性保障总览

| 风险点 | 应对策略 |
|--------|---------|
| 并发核销同一笔应收/应付 | `SELECT ... FOR UPDATE` 行锁，后端再次校验余额 |
| 核销单作废后余额回滚异常 | 事务 + 行锁 + 作废前校验 received_amount ≥ write_off_amount |
| 编辑核销单时的原子性 | 先回滚旧明细 → 校验 → 应用新明细，全在同一事务中 |
| 历史数据 balance_amount 为 0 | 迁移脚本初始化：`UPDATE receivables SET balance_amount = amount - received_amount` |
| 核销单明细与主表 type 不一致 | 后端创建时强制 `item.source_type = document.type`，不信任前端传值 |

## 五、API 设计

### 5.1 接口清单

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/write-off` | 获取核销单列表（分页+筛选） |
| GET | `/api/write-off/summary` | 汇总统计 |
| GET | `/api/write-off/next-number` | 获取下一个核销单编号 |
| GET | `/api/write-off/:id` | 获取核销单详情（含明细） |
| GET | `/api/write-off/pending-records` | 获取待核销的应收/应付账款 |
| POST | `/api/write-off` | 创建核销单（事务） |
| PUT | `/api/write-off/:id` | 编辑核销单（事务，先回滚再应用） |
| PUT | `/api/write-off/:id/void` | 作废核销单（软删除+回滚，**不是** DELETE） |

> **接口命名说明：** 作废使用 `PUT /:id/void` 而非 `DELETE /:id`，因为是软删除（设 status=0），物理删除会丢失审计记录。

### 5.2 关键接口详细设计

#### `GET /api/write-off/pending-records`

获取指定客户/供应商下待核销的账款列表：

```
Query Params:
  type: 1|2           -- 核销类型
  entity_id: string   -- 客户/供应商代码

Response:
  {
    data: [
      {
        receivable_id,            -- 账款ID
        source_bill_id,           -- 来源单据号（出库单号/入库单号）
        source_bill_type,         -- 来源类型（出库单/退货单）
        amount,                   -- 应收/应付总额
        handling_fee,             -- 手续费
        receivable_total,         -- = amount + handling_fee，可核销总额
        received_amount,          -- 已核销金额
        balance_amount,           -- 待核销余额 = receivable_total - received_amount
        status,                   -- 结算状态
        payment_method,           -- 结算方式（可作为默认值）
        delivery_time             -- 出库/入库时间
      }
    ]
  }
```

#### `POST /api/write-off`

创建核销单，事务处理：

```json
{
  "type": 1,
  "entity_id": "C001",
  "entity_name": "客户A",
  "write_off_date": "2026-09-20",
  "payment_method": "银行转账",
  "bank_reference": "BOC20260920001",
  "remarks": "",
  "items": [
    {
      "source_id": "rec-uuid-1",
      "source_bill_id": "CK20260901001",
      "write_off_amount": 30000
    }
  ]
}
```

> **注意：** 请求中不需要传 `source_type` 和 `target_amount`。`source_type` 由后端从主表 `type` 自动赋值；`target_amount`、`before_received`、`after_received` 由后端从数据库读取后写入。

后端事务逻辑：
```
BEGIN TRANSACTION
  1. 校验：每条 item.write_off_amount > 0
  2. INSERT write_off_documents（total_amount 先设为 0）

  3. FOR EACH item:
     -- 行锁读取最新余额
     row = SELECT * FROM receivables WHERE receivable_id = item.source_id FOR UPDATE

     -- 校验
     if (row.received_amount + item.write_off_amount > row.amount + row.handling_fee)
       → ROLLBACK, 返回错误

     -- 写入明细（含快照）
     INSERT write_off_items (
       target_amount   = row.amount,
       before_received = row.received_amount,
       write_off_amount = item.write_off_amount,
       after_received  = row.received_amount + item.write_off_amount,
       source_type     = document.type  -- 从主表取，不信任前端
     )

     -- 更新应收/应付
     UPDATE receivables SET
       received_amount = row.received_amount + item.write_off_amount,
       balance_amount  = (row.amount + row.handling_fee) - (row.received_amount + item.write_off_amount),
       status = CASE
         WHEN (row.received_amount + item.write_off_amount) >= (row.amount + row.handling_fee) THEN 2
         WHEN (row.received_amount + item.write_off_amount) > 0 THEN 1
         ELSE 0
       END
     WHERE receivable_id = item.source_id

  4. UPDATE write_off_documents SET total_amount = SUM(明细.write_off_amount)

COMMIT
```

#### `PUT /api/write-off/:id/void`

作废核销单：

```
后端事务逻辑：
BEGIN TRANSACTION
  1. 读取核销单，校验 status = 1（只有已核销的才能作废）

  2. FOR EACH item:
     row = SELECT received_amount FROM receivables WHERE receivable_id = item.source_id FOR UPDATE

     -- 安全校验
     if (row.received_amount < item.write_off_amount)
       → ROLLBACK, 返回错误："数据异常，当前已核销金额小于本次回滚金额"

     -- 回滚
     UPDATE receivables SET
       received_amount = row.received_amount - item.write_off_amount,
       balance_amount  = (amount + handling_fee) - (received_amount - item.write_off_amount),
       status = CASE ... 重新计算
     WHERE receivable_id = item.source_id

  3. UPDATE write_off_documents SET status = 0

COMMIT
```

  write_off_id       VARCHAR(36) PRIMARY KEY,

  entity_id          VARCHAR(50) NOT NULL,

  total_amount       DECIMAL(14,4) DEFAULT 0,
  payment_method     VARCHAR(50),
  bank_reference     VARCHAR(100),
  remarks            TEXT,
  status             TINYINT DEFAULT 1 COMMENT '1=已核销 0=已作废',
  document_date      DATE,
  create_time        DATETIME DEFAULT CURRENT_TIMESTAMP,

  INDEX idx_entity_id (entity_id),
  INDEX idx_write_off_date (write_off_date),
  INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ============================================================
-- 2. 创建核销单明细表
-- ============================================================
CREATE TABLE IF NOT EXISTS write_off_items (
  item_id            VARCHAR(36) PRIMARY KEY,
  write_off_id       VARCHAR(36) NOT NULL,
  source_type        TINYINT NOT NULL COMMENT '1=应收 2=应付',
  source_id          VARCHAR(36) NOT NULL,
  source_bill_id     VARCHAR(50),
  target_amount      DECIMAL(14,4) DEFAULT 0,
  write_off_amount   DECIMAL(14,4) DEFAULT 0,
  before_received    DECIMAL(14,4) DEFAULT 0,
  after_received     DECIMAL(14,4) DEFAULT 0,
  remarks            VARCHAR(200),
  create_time        DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (write_off_id) REFERENCES write_off_documents(write_off_id),
  INDEX idx_write_off_id (write_off_id),
  INDEX idx_source (source_type, source_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ============================================================
-- 3. 历史数据初始化（关键！）
--    现有应收/应付数据的 balance_amount 从未被正确计算，
--    需要在核销单功能上线前补齐，否则待核销余额显示错误。
-- ============================================================
UPDATE receivables
SET balance_amount = amount + IFNULL(handling_fee, 0) - IFNULL(received_amount, 0)
WHERE balance_amount = 0 AND amount > 0;

UPDATE payables
SET balance_amount = amount + IFNULL(handling_fee, 0) - IFNULL(received_amount, 0)
WHERE balance_amount = 0 AND amount > 0;

## 九、注意事项

1. **事务一致性**：创建、编辑、作废核销单**必须**使用数据库事务，确保应收/应付状态与核销单一致
2. **并发控制**：同一笔应收/应付可能被多张核销单核销，**必须**使用 `SELECT ... FOR UPDATE` 行锁防止超额核销
3. **校验规则**：本次核销金额 ≤ `amount + handling_fee - received_amount`（含手续费的待核销余额）
4. **编号规则**：使用 `hx` 前缀 + 日期 + 3位序号（如 `hx20260920001`），与对账单 `pr` 前缀区分
5. **权限控制**：核销单涉及资金操作，后续可考虑增加审批流程
6. **源类型一致性**：后端创建核销单时，`item.source_type` 必须从主表 `type` 取值，不信任前端传入
7. **编辑安全**：编辑核销单的逻辑是"先回滚旧明细 → 校验 → 应用新明细"，全在同一事务中完成
8. **作废不可逆**：作废后的核销单不可重新启用，只能查看，确保审计完整性
9. **历史数据**：上线前需执行迁移脚本，将现有 `balance_amount = 0` 的记录补正
